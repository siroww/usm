## Общая идея

`Math` — это **утилитарный класс**, просто склад готовых статических методов для математики. Все методы вызываются прямо через `Math.методИмя()`, без создания объекта — как мы уже видели с `Integer.parseInt()`. `Math` находится в `java.lang`, поэтому **импортировать не нужно** — он доступен всегда автоматически.

---

## 1. Округление чисел

### Math.round() — обычное округление

```java
double a = 5.6;
System.out.println(Math.round(a)); // 6 — округлило вверх (>= .5)

double b = 5.4;
System.out.println(Math.round(b)); // 5 — округлило вниз (< .5)
```

⚠️ Возвращает `long` если на входе `double`, и `int` если на входе `float`. Будь внимателен с типом переменной куда сохраняешь результат.

### Math.ceil() — округление ВВЕРХ, всегда

```java
double a = 9.99;
System.out.println(Math.ceil(a)); // 10.0

double b = 9.01;
System.out.println(Math.ceil(b)); // 10.0 — даже маленький "хвостик" поднимает вверх
```

### Math.floor() — округление ВНИЗ, всегда

```java
double a = 9.99;
System.out.println(Math.floor(a)); // 9.0 — даже почти 10, всё равно отбрасывает вниз
```

**Сравнение всех трёх на одном числе:**

```java
double x = 7.5;
System.out.println(Math.round(x)); // 8  — обычное округление по правилам
System.out.println(Math.ceil(x));  // 8.0 — вверх
System.out.println(Math.floor(x)); // 7.0 — вниз
```

⚠️ Обрати внимание: `ceil()` и `floor()` возвращают `double`, а `round()` возвращает `long`/`int`. Это частая причина ошибок компиляции у новичков.

## 2. Абсолютное значение (модуль)

```java
System.out.println(Math.abs(-25));   // 25
System.out.println(Math.abs(25));    // 25
System.out.println(Math.abs(-3.14)); // 3.14
```

Превращает отрицательное число в положительное, положительное оставляет как есть. Часто нужен когда важна **разница** между числами, а не направление:

```java
int a = 5, b = 10;
System.out.println(Math.abs(a - b)); // 5 (не -5)
```

## 3. Максимум и минимум

```java
System.out.println(Math.max(10, 20)); // 20
System.out.println(Math.min(10, 20)); // 10

// Работает и с double
System.out.println(Math.max(3.5, 2.1)); // 3.5
```

⚠️ `Math.max()` и `Math.min()` принимают **только два** аргумента за раз. Если нужно найти максимум из трёх и более чисел — вкладывай вызовы друг в друга:

```java
int a = 5, b = 12, c = 8;
int maxOfThree = Math.max(a, Math.max(b, c));
System.out.println(maxOfThree); // 12
```

## 4. Степени и корни

### Math.pow() — возведение в степень

```java
System.out.println(Math.pow(2, 8)); // 256.0
System.out.println(Math.pow(5, 2)); // 25.0
```

⚠️ Math.pow() всегда возвращает double, даже если результат целое число — то есть `256.0`, а не `256`. Если нужен `int` — приводи через cast.

### Math.sqrt() — квадратный корень

```java
System.out.println(Math.sqrt(25)); // 5.0
System.out.println(Math.sqrt(2));  // 1.4142135623730951
```

### Math.cbrt() — кубический корень

```java
System.out.println(Math.cbrt(27)); // 3.0
```

## 5. Логарифмы и экспонента

```java
double a = 10;

System.out.println(Math.log(a));   // 2.302585092994046 — натуральный логарифм (по основанию e)
System.out.println(Math.log10(a)); // 1.0 — логарифм по основанию 10
System.out.println(Math.exp(a));   // 22026.465794806718 — e в степени a
```

`Math.log()` — это натуральный логарифм (`ln`), не десятичный! Частая ошибка новичков — путать `log()` с `log10()`. Если нужен именно по основанию 10 — используй `log10()`.

## 6. Тригонометрия

### ⚠️ Главное правило — всё в радианах, не в градусах!

Это самая важная деталь во всей теме. Java **не понимает градусы** напрямую — все тригонометрические методы работают только с **радианами**.

```java
// НЕПРАВИЛЬНО — если думаешь что это 45 градусов
System.out.println(Math.sin(45)); // 0.8509035245341184 — это НЕ синус 45°!

// ПРАВИЛЬНО — сначала перевести градусы в радианы
double radians = Math.toRadians(45);
System.out.println(Math.sin(radians)); // 0.7071067811865475 — а вот это правильный синус 45°
```

Если забудешь перевести — получишь число, но это будет синус **45 радиан**, а не 45 градусов, и это совершенно другое значение.

---

### 1. Перевод между градусами и радианами

#### Math.toRadians() — градусы → радианы

```java
double degrees = 180;
double radians = Math.toRadians(degrees);
System.out.println(radians); // 3.141592653589793 (это и есть π)
```

#### Math.toDegrees() — радианы → градусы

```java
double radians = Math.PI;
double degrees = Math.toDegrees(radians);
System.out.println(degrees); // 180.0
```

**Запомни простое соответствие:** `180°` это всегда `π` радиан. Отсюда формула вручную (если бы метода не было):

```java
double radians = degrees * (Math.PI / 180);
double degrees2 = radians * (180 / Math.PI);
```

Но проще и безопаснее использовать готовые `toRadians()`/`toDegrees()` — меньше шанс ошибиться в формуле.

---

### 2. Основные тригонометрические функции

```java
double angle = Math.toRadians(45); // переводим 45° в радианы

System.out.println(Math.sin(angle)); // синус — 0.7071067811865475
System.out.println(Math.cos(angle)); // косинус — 0.7071067811865476
System.out.println(Math.tan(angle)); // тангенс — 0.9999999999999999 (округление из-за double)
```

⚠️ Заметь — `tan(45°)` математически равен ровно `1`, но Java выводит `0.9999999999999999`. Это не ошибка Java — это особенность хранения дробных чисел типа `double` в принципе (ограниченная точность). Не пугайся таких мелких отклонений в последних знаках.

---

### 3. Обратные тригонометрические функции (арк-функции)

Это функции "в обратную сторону" — даёшь готовое значение синуса/косинуса/тангенса, а получаешь **угол** (в радианах!).

```java
double value = 1.0;

System.out.println(Math.asin(value)); // арксинус — 1.5707963267948966 (это π/2 радиан = 90°)
System.out.println(Math.acos(value)); // арккосинус — 0.0 (это 0°)
System.out.println(Math.atan(value)); // арктангенс — 0.7853981633974483 (это π/4 радиан = 45°)
```

**Важно:** результат этих методов — **радианы**, поэтому если хочешь увидеть привычные градусы, переводи обратно:

```java
double value = 1.0;
double angleInRadians = Math.atan(value);
double angleInDegrees = Math.toDegrees(angleInRadians);
System.out.println(angleInDegrees); // 45.0
```

---

### 4. atan2() — особый, "умный" арктангенс

Это более продвинутый вариант `atan()`, который принимает **два** аргумента (координаты Y и X) вместо одного отношения, и правильно определяет угол **в любой четверти** координатной плоскости:

```java
double y = 1.0;
double x = 1.0;

System.out.println(Math.atan2(y, x)); // 0.7853981633974483 (45°)
```

**Зачем это нужно**, если уже есть обычный `atan()`: обычный `Math.atan(y / x)` не может различить например точку `(1, 1)` от точки `(-1, -1)` — для обоих случаев `y/x` даёт одинаковое отношение `1`, хотя на самом деле это совершенно разные углы (одна точка в первой четверти, другая в третьей). `atan2()` смотрит на знаки `x` и `y` отдельно и поэтому всегда выдаёт правильный угол.

Это уже доввольно продвинутая тема (используется в графике, играх, навигации), для текущего уровня просто знай что такой метод существует.

---

### 5. Гиперболические функции (для общего развития)

Это "родственники" обычных тригонометрических функций, но из другой математической области (гиперболическая геометрия):

```java
double x = 1.0;

System.out.println(Math.sinh(x)); // гиперболический синус — 1.1752011936438014
System.out.println(Math.cosh(x)); // гиперболический косинус — 1.5430806348152437
System.out.println(Math.tanh(x)); // гиперболический тангенс — 0.7615941559557649
```

На твоём уровне сейчас это не пригодится в обычных задачах — встретишь их позже, например `tanh` иногда всплывает в нейросетях как функция активации. Пока просто знай что они есть в `Math`.

## 7. Случайные числа — Math.random()

```java
double r = Math.random();
System.out.println(r); // случайное число от 0.0 (включительно) до 1.0 (НЕ включительно)
```

Math.random() возвращает double. Чтобы получить целое число, нужно привести через (int).

### Как получить случайное целое число в нужном диапазоне

Формула для случайного числа от 0 до 100 включительно: (int)(Math.random() * 101)

```java
int randomNum = (int)(Math.random() * 101); // от 0 до 100
System.out.println(randomNum);
```

**Общая формула для диапазона [min, max]:**

```java
int min = 5, max = 15;
int random = min + (int)(Math.random() * (max - min + 1));
System.out.println(random); // случайное число от 5 до 15 включительно
```

Разбор формулы: `Math.random() * (max - min + 1)` даёт число от `0` до `(max-min)`, потом добавляем `min` чтобы сдвинуть диапазон в нужное место. `+1` нужен потому что `Math.random()` никогда не достигает верхней границы `1.0`.

## 8. Константы класса Math

### Полный список

```java
System.out.println(Math.PI); // 3.141592653589793
System.out.println(Math.E);  // 2.718281828459045
```

Это всё, других констант в `Math` больше нет — только эти две.

---

### Math.PI — число π (пи)

Используется в формулах с окружностями, кругами, углами:

```java
double radius = 5;

double circleArea = Math.PI * radius * radius;        // площадь круга
double circumference = 2 * Math.PI * radius;            // длина окружности

System.out.println(circleArea);      // 78.53981633974483
System.out.println(circumference);  // 31.41592653589793
```

Также используется при переводе градусов в радианы (для тригонометрии):

```java
double degrees = 180;
double radians = degrees * (Math.PI / 180);
System.out.println(radians); // 3.141592653589793
```

(Хотя для этого есть готовый метод `Math.toRadians()`, который мы разбирали в прошлой теме — `Math.PI` нужен когда хочешь написать формулу вручную.)

---

### Math.E — число Эйлера (основание натурального логарифма)

Используется в формулах с натуральным логарифмом и экспонентой:

```java
System.out.println(Math.E); // 2.718281828459045

// Math.exp(1) даёт ровно Math.E, потому что e^1 = e
System.out.println(Math.exp(1)); // 2.718281828459045
```

Применяется реже чем `Math.PI` на твоём уровне — встретишь в задачах на логарифмический рост, проценты с непрерывным начислением, и подобных более продвинутых темах.

---

### Важная деталь — обе константы это `public static final double`

```java
// Это значит:
// public  — доступны откуда угодно
// static  — обращаешься через имя класса, без создания объекта
// final   — нельзя изменить значение, это константа навсегда
```

Попытка изменить даст ошибку компиляции:

```java
Math.PI = 4; // ОШИБКА! Cannot assign a value to final variable 'PI'
```

Это логично — представь если бы кто-то мог "поменять" число π в середине программы 😄

---

### Точность

Обе константы хранятся как `double`, то есть с ограниченной точностью (около 15-17 значащих цифр). Для абсолютного большинства задач этого хватает с большим запасом — в реальной разработке никто не считает руками точнее этого.

## 9. Остаток и гипотенуза

### Math.hypot() — гипотенуза прямоугольного треугольника

Вместо того чтобы писать `Math.sqrt(a*a + b*b)` вручную — есть готовый метод:

```java
double a = 3, b = 4;
System.out.println(Math.hypot(a, b)); // 5.0 — классический треугольник 3-4-5
```

### Math.floorDiv() и Math.floorMod() — деление и остаток с поведением для отрицательных чисел

```java
System.out.println(-7 / 2);              // -3 (обычное деление int, округляет к нулю)
System.out.println(Math.floorDiv(-7, 2)); // -4 (округляет вниз, "правильнее" математически)

System.out.println(-7 % 2);               // -1 (обычный остаток может быть отрицательным!)
System.out.println(Math.floorMod(-7, 2)); // 1  (всегда возвращает положительный остаток)
```

Это полезно знать — обычный оператор `%` в Java может выдавать отрицательный остаток, что иногда неожиданно. `floorMod()` решает эту проблему, если тебе всегда нужен положительный результат.

## 10. Глубина — что добавить сверх базовых знаний

### А) Все методы Math — статические

Все методы класса Math статические — то есть вызываются прямо через имя класса `Math.метод()`, никогда не нужно писать `new Math()`. Это потому что у `Math` нет смысла создавать "объекты" — это просто набор универсальных формул, которые не хранят никакого состояния.

### Б) Методы с защитой от переполнения — *Exact

Java предоставляет специальные "безопасные" версии арифметики, которые **выбрасывают ошибку** вместо того чтобы тихо дать неправильный результат при переполнении:

```java
int max = Integer.MAX_VALUE; // самое большое число которое может вместить int

System.out.println(max + 1); // -2147483648 — переполнение, тихо сломалось, никакой ошибки!

System.out.println(Math.addExact(max, 1)); // ОШИБКА — ArithmeticException, явно сообщает о проблеме
```

Другие подобные методы: `Math.subtractExact()`, `Math.multiplyExact()`, `Math.toIntExact()` (безопасно превращает `long` в `int`, с ошибкой если число не влезает).

Это очень полезно знать на уровне "продвинутого" программиста — обычная арифметика в Java может **молча сломаться** при переполнении, и это одна из самых коварных багов которые сложно отследить. `*Exact` методы — это защита от такого сценария.

### В) StrictMath — "близкий родственник" Math

Класс Math содержит методы для базовых числовых операций. В отличие от некоторых методов класса StrictMath, реализации эквивалентных функций класса Math не обязаны возвращать побитово одинаковые результаты на разных платформах. Простыми словами: `Math` может давать чуть-чуть разные результаты на разных компьютерах/системах (на уровне последних знаков после запятой) ради скорости. `StrictMath` гарантирует абсолютно одинаковый результат везде, но работает медленнее. Для твоего уровня сейчас и 99% реальных задач — `Math` более чем достаточен, `StrictMath` нужен только в специфичных научных вычислениях где критична побитовая точность.

### Г) Гиперболические функции — для продвинутых

Помимо обычных синуса/косинуса есть и гиперболические версии:

```java
double a = 1.0;
System.out.println(Math.sinh(a)); // гиперболический синус
System.out.println(Math.cosh(a)); // гиперболический косинус
System.out.println(Math.tanh(a)); // гиперболический тангенс
```

Используются в более продвинутой математике (например, в нейросетях `tanh` встречается как функция активации) — пока просто знай что они существуют, в начальных задачах не понадобятся.

## 12. Округление до N знаков после запятой

## Способ 1 — через Math.round() и масштабирование (из твоего материала)

```java
double x = 25.364789;
int n = 3; // сколько знаков после запятой нужно
double scale = Math.pow(10, n); // scale = 1000.0

System.out.println(Math.round(x * scale) / scale); // 25.365
```

**Как это работает по шагам:**

```
x * scale = 25.364789 * 1000 = 25364.789
Math.round(25364.789) = 25365          ← округлили до целого
25365 / scale = 25365 / 1000 = 25.365  ← вернули дробную часть на место
```

Идея: умножаем на `10^n`, чтобы нужные тебе знаки "стали" целой частью числа, округляем как обычное целое, потом делим обратно чтобы вернуть запятую на нужное место.

⚠️ **Важная деталь которую отметил твой материал** — у этого способа **низкая точность** из-за того, что `double` физически не может хранить дробные числа абсолютно точно (это особенность того, как компьютер хранит дробные числа в принципе, не только в Java). Для 2-4 знаков после запятой в простых задачах — нормально, но не используй этот способ для денег или научных расчётов где точность критична (там нужен специальный класс `BigDecimal`, но это уже более продвинутая тема для будущего).

**Результат остаётся типом `double`** — то есть с этим числом можно дальше делать математику (складывать, умножать и т.д.).

---

## Способ 2 — через String.format() (из твоего материала)

```java
double x = 25.364789;
String formatted = String.format("%.3f", x);
System.out.println(formatted); // 25.365
```

**Разбор синтаксиса `"%.3f"`:**

- `%` — начало форматирующей конструкции
- `.3` — сколько знаков после запятой оставить
- `f` — тип данных, **f**loat (число с плавающей точкой)

**Главное отличие от Способа 1:** результат — это **`String`, а не число**. То есть `formatted` это текст `"25.365"`, а не число `25.365`. Если попробуешь сделать с ним математику — будет ошибка:

```java
String formatted = String.format("%.3f", x);
double result = formatted + 5; // ОШИБКА! formatted это String, не число
```

Если нужно и округлить, и продолжить считать дальше — придётся преобразовать строку обратно в число через `Double.parseDouble()` (это мы разбирали в теме про конвертацию типов):

```java
String formatted = String.format("%.3f", x);
double backToNumber = Double.parseDouble(formatted);
```

Но если округление нужно **только для вывода на экран** — `String.format()` это самый чистый и читаемый способ, без всякого ручного умножения-деления.

---

## Способ 3 — через System.out.printf() (бонус, ты его уже видел раньше!)

Помнишь в самой первой нашей теме я показывал `printf()` для вывода переменных? Та же логика работает и для округления:

```java
double x = 25.364789;
System.out.printf("%.3f%n", x); // 25.365
```

Это просто комбинация — `printf()` сразу выводит на экран отформатированное число, без промежуточной переменной `String`. По сути это `String.format()`, только сразу с печатью результата. Используй когда тебе не нужно сохранять округлённое значение, а просто хочешь красиво вывести его сразу.

---

## Сравнение всех трёх способов

|Способ|Возвращает|Когда использовать|
|---|---|---|
|`Math.round(x * scale) / scale`|`double` (число)|Когда нужно **продолжить вычисления** с округлённым числом|
|`String.format("%.Nf", x)`|`String` (текст)|Когда нужна **строка** для дальнейшей обработки текста|
|`System.out.printf("%.Nf%n", x)`|ничего (печатает сразу)|Когда нужно **просто вывести** красиво на экран, без сохранения|

---

## Наглядный пример различия

```java
double price = 19.998;

// Способ 1 — для расчётов
double roundedPrice = Math.round(price * 100) / 100.0;
double total = roundedPrice * 3; // можно дальше считать!
System.out.println(total); // 60.0

// Способ 2 — для вывода как текст
String displayPrice = String.format("%.2f", price);
System.out.println("Цена: " + displayPrice + " руб."); // Цена: 20.00 руб.

// Способ 3 — для немедленного вывода
System.out.printf("Итого: %.2f руб.%n", price); // Итого: 20.00 руб.
```

Обрати внимание на разницу в выводе между Способом 1 и Способами 2-3: `Math.round()` даёт `20.0` (один ноль после точки, потому что это просто `double`, и Java не показывает лишние нули), а форматирование строки даёт `20.00` (ровно два знака, как ты попросил) — это ещё одна причина почему для **визуального вывода** лучше использовать форматирование строки, а не Math.round().

---

## Главный вывод

Если нужно **посчитать дальше** с округлённым числом — используй `Math.round()` со scale. Если нужно просто **красиво показать** число пользователю — используй `String.format()` или `printf()`, они дают предсказуемое количество знаков после запятой, в отличие от `Math.round()` который может "съесть" незначащие нули 💪

# Java — Шпаргалка: округление чисел (когда что применять)

## Главное правило — раздели задачу на 2 типа

Перед тем как выбирать метод, ответь себе на вопрос:

**Вопрос:** Мне нужно ЧИСЛО (чтобы дальше считать) или ТЕКСТ (чтобы красиво показать)?

Это разделение решает 90% путаницы с округлением в Java.

---

## Тип задачи 1 — нужно ЧИСЛО (double), с которым можно работать дальше

### Главный метод — Math.round() + масштабирование

```java
double x = 25.364789;
int n = 3; // сколько знаков после запятой

double rounded = Math.round(x * Math.pow(10, n)) / Math.pow(10, n);
System.out.println(rounded); // 25.365
```

**Как это работает (суть, не зубрёжка):**

1. Умножаем на `10^n` — нужные знаки "становятся" целой частью
2. `Math.round()` округляет как целое число
3. Делим обратно на `10^n` — возвращаем запятую на место

**Результат — настоящий `double`**, можно дальше умножать, складывать, сравнивать.

```java
double rounded = Math.round(25.364789 * 1000) / 1000.0;
double total = rounded * 2; // спокойно работает дальше
System.out.println(total); // 50.73
```

**Бонус:** `double` сам по себе не хранит "лишние нули" — поэтому если результат `11.5`, напечатается именно `11.5`, а не `11.50000`. Это идеально подходит когда условие задачи говорит "не выводи лишние нули".

⚠️ **Когда использовать:** учебные задачи, обычные расчёты, когда нужно и округлить, и продолжить вычисления, и финальный тип должен остаться `double`.

---

## Тип задачи 2 — нужен ТЕКСТ для красивого отображения

### Метод — String.format()

```java
double x = 25.364789;
String formatted = String.format("%.3f", x);
System.out.println(formatted); // 25.365
```

**Результат — это `String`**, не число. `"%.3f"` означает "ровно 3 знака после запятой, всегда, даже если надо добавить нули":

```java
double y = 5.1;
String formatted2 = String.format("%.3f", y);
System.out.println(formatted2); // 5.100 — добавил нули принудительно!
```

⚠️ **Важное отличие от Способа 1:** `String.format()` **всегда** даёт ровно N знаков, добивая нулями. Если тебе нужно убрать лишние нули — этот способ **не подходит**, бери Тип задачи 1.

**Когда использовать:** когда нужна именно строка для вывода (например "Цена: 19.50 руб." — тут нули нужны, это нормальный денежный формат), и дальнейшая математика с этим числом не требуется.

### Аналог — printf() (то же самое, но без сохранения в переменную)

```java
double x = 25.364789;
System.out.printf("%.3f%n", x); // печатает сразу: 25.365
```

Разница с `String.format()` только в том, что `printf()` сразу печатает, а не возвращает строку для дальнейшего использования.

---

## Тип задачи 3 (редко нужен на твоём уровне) — экстремальная точность

### BigDecimal — когда double недостаточно точен

```java
import java.math.BigDecimal;
import java.math.RoundingMode;

BigDecimal bd = BigDecimal.valueOf(25.364789);
bd = bd.setScale(3, RoundingMode.HALF_UP);
System.out.println(bd); // 25.365
```

**Когда использовать:** работа с деньгами в реальных приложениях, банковские расчёты, научные вычисления где погрешность `double` критична. BigDecimal — золотой стандарт для точной десятичной арифметики, он избегает ошибок плавающей точки благодаря арифметике произвольной точности.

⚠️ Для твоих текущих задач на Stepik — **не нужен**. Это инструмент для серьёзных проектов, не для учебных примеров с 2-5 знаками после запятой.

---

## Итоговая сравнительная таблица

|Способ|Тип результата|Лишние нули|Когда использовать|
|---|---|---|---|
|`Math.round(x * 10^n) / 10^n`|`double`|**Убирает** автоматически|Нужно число для расчётов, и/или условие "без лишних нулей"|
|`String.format("%.Nf", x)`|`String`|**Добавляет** принудительно|Нужен текст для вывода, нули — это нормально (например деньги)|
|`printf("%.Nf%n", x)`|ничего (печать)|**Добавляет** принудительно|То же что выше, но без сохранения в переменную|
|`BigDecimal.setScale(n, mode)`|`BigDecimal`|Зависит от настроек|Экстремальная точность — деньги, научные расчёты|

---

## Как выбирать за 5 секунд — простой алгоритм

```
1. Условие задачи просит вернуть double? 
   → Math.round(x * 10^n) / 10^n

2. Условие просит "без лишних нулей"?
   → Math.round(x * 10^n) / 10^n

3. Условие просит "ровно N знаков, даже если там нули" (например для денег)?
   → String.format("%.Nf", x)

4. Работаешь с реальными деньгами в серьёзном проекте?
   → BigDecimal

5. Не уверен, что выбрать?
   → Math.round(x * 10^n) / 10^n — это твой дефолтный, самый универсальный вариант
```

---

## Твой главный способ на запомнить навсегда

```java
double rounded = Math.round(число * Math.pow(10, n)) / Math.pow(10, n);
```

Это закрывает 90% твоих учебных задач. Остальное — это нюансы для специфичных случаев, которые встретишь по необходимости, не нужно зубрить заранее 💪

```java
double result = Math.pow(Math.pow(x, y), 1.0/n); 
double rounded = Math.round(result * 100000) / 100000.0;
```
