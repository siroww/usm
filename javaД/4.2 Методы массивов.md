## Импорт — обязательно в начале файла

```java
import java.util.Arrays;
```

Без этой строки ничего из класса `Arrays` использовать не получится — компилятор не поймёт что ты имеешь в виду.

---

## 1. Arrays.toString() — превратить массив в читаемую строку

```java
int[] array = {1, 2, 3, 4, 5};

System.out.println(array);              // [I@1b6d3586 — бесполезный хеш-код!
System.out.println(Arrays.toString(array)); // [1, 2, 3, 4, 5]
```

**Почему обычный `println(array)` не работает нормально:** массив это объект, а не примитив. Когда печатаешь объект без специального метода — Java по умолчанию печатает **техническую информацию** про этот объект (тип + адрес в памяти в шестнадцатеричном виде), а не его содержимое.

`Arrays.toString()` — единственный нормальный способ увидеть содержимое массива сразу и быстро. Используй его **всегда**, когда хочешь вывести массив для отладки или проверки.

## 2. Arrays.sort() — сортировка "на месте"

```java
int[] array = {5, 10, 15, 4, 1};
Arrays.sort(array);
System.out.println(Arrays.toString(array)); // [1, 4, 5, 10, 15]
```

⚠️ **Самый важный момент темы** — метод **ничего не возвращает** (`void`), он **меняет сам исходный массив**. Это называется "сортировка на месте" (in-place).

```java
int[] array = {5, 10, 15};
int[] result = Arrays.sort(array); // ОШИБКА компиляции! sort() ничего не возвращает
```

Правильно — просто вызвать метод, и сам `array` уже будет отсортирован после этого:

```java
int[] array = {5, 10, 15};
Arrays.sort(array); // вызвали, и всё — array теперь отсортирован
System.out.println(Arrays.toString(array)); // [5, 10, 15]
```

### Сортировка части массива

```java
int[] array = {5, 10, 15, 4, 1, 7, 23, 8, 11, 42};
Arrays.sort(array, 3, 7);
System.out.println(Arrays.toString(array)); // [5, 10, 15, 1, 4, 7, 23, 8, 11, 42]
```

Здесь сортируются только элементы с индексами `3, 4, 5, 6` — то есть `{4, 1, 7, 23}` превращаются в `{1, 4, 7, 23}`, а остальные элементы массива не трогаются. ⚠️ Правая граница (`7`) **не включается** — точно такая же логика как у `substring()` в строках, которую мы разбирали раньше.

### Сортировка строк — лексикографический порядок

```java
String[] array = {"one", "two", "three", "four"};
Arrays.sort(array);
System.out.println(Arrays.toString(array)); // [four, one, three, two]
```

"Лексикографический" — это значит **алфавитный**, как в словаре, а не по длине слова или смыслу. Сравниваются буквы по очереди как в `String.compareTo()` (это уже немного забегая вперёд, но полезно знать само слово).

⚠️ **Важный нюанс который твой конспект не упомянул:** строки сортируются с учётом регистра! Заглавные буквы идут **раньше** строчных в таблице символов:

```java
String[] arr = {"banana", "Apple", "cherry"};
Arrays.sort(arr);
System.out.println(Arrays.toString(arr)); // [Apple, banana, cherry]
```

`"Apple"` оказался первым не потому что по алфавиту, а потому что заглавная `A` имеет **меньший код** в таблице символов чем строчная `b`. Если нужна сортировка без учёта регистра — есть `Arrays.sort(arr, String.CASE_INSENSITIVE_ORDER)`, но это уже продвинутый момент для будущего.

## 3. Arrays.equals() — сравнение массивов

```java
int[] numbers1 = {1, 2, 3};
int[] numbers2 = {1, 2, 3};

System.out.println(Arrays.equals(numbers1, numbers2)); // true
```

⚠️ **Это прямое продолжение темы которую мы разбирали в строках** — помнишь, я говорил никогда не сравнивать `String` через `==`, а использовать `.equals()`? С массивами та же логика, но есть важное отличие в **синтаксисе вызова**:

```java
int[] numbers1 = {1, 2, 3};
int[] numbers2 = {1, 2, 3};

System.out.println(numbers1.equals(numbers2)); // false! Это НЕ работает как со строками!
System.out.println(Arrays.equals(numbers1, numbers2)); // true — а вот это правильно
```

**Почему `.equals()` не работает напрямую у массивов, хотя работал у строк:** класс `String` **переопределил** метод `.equals()`, чтобы он сравнивал содержимое (это будет понятнее когда дойдёшь до темы ООП и переопределения методов). А класс массива **не переопределяет** `.equals()` — поэтому он использует стандартное поведение, которое сравнивает **ссылки** (то есть адреса в памяти), а не содержимое. Именно поэтому для массивов нужен отдельный **статический** метод `Arrays.equals()`, а не вызов через точку у самого массива.

**Запомни простое правило:** для **строк** — `.equals()` через точку у объекта. Для **массивов** — `Arrays.equals()` через сам класс `Arrays`.

## 4. Arrays.copyOf() — настоящая копия массива

Это прямое продолжение того, о чём мы говорили в прошлой теме — массивы **ссылочный тип**, и простое присваивание не создаёт копию.

```java
int[] numbers1 = {1, 2, 3, 4, 5};
int[] numbers2 = numbers1; // numbers2 указывает на ТОТ ЖЕ массив!
int[] numbers3 = Arrays.copyOf(numbers1, numbers1.length); // а это НАСТОЯЩАЯ копия

numbers1[3] = 1000;

System.out.println(Arrays.toString(numbers2)); // [1, 2, 3, 1000, 5] — изменился тоже!
System.out.println(Arrays.toString(numbers3)); // [1, 2, 3, 4, 5] — остался прежним!
```

**Второй аргумент `copyOf()`** — это **сколько элементов** скопировать, начиная с первого:

```java
int[] numbers1 = {1, 2, 3, 4, 5};

int[] numbers2 = Arrays.copyOf(numbers1, 3); // взять только первые 3
System.out.println(Arrays.toString(numbers2)); // [1, 2, 3]
```

### Бонус, которого нет в твоём конспекте — copyOf() может и УВЕЛИЧИВАТЬ массив

```java
int[] numbers1 = {1, 2, 3};
int[] numbers2 = Arrays.copyOf(numbers1, 5); // просим БОЛЬШЕ элементов чем есть
System.out.println(Arrays.toString(numbers2)); // [1, 2, 3, 0, 0]
```

Если просишь скопировать **больше** элементов, чем есть в оригинале — недостающие места заполняются значениями по умолчанию (для `int` это `0`, как мы разбирали раньше). Это, кстати, единственный простой способ "увеличить" массив в Java, раз размер массива нельзя поменять напрямую — создаёшь новый, побольше, через `copyOf()`.

## 5. Arrays.copyOfRange() — копия куска массива

```java
int[] numbers1 = {2, 4, 6, 8, 10, 12, 14, 16};

int[] numbers2 = Arrays.copyOfRange(numbers1, 2, 5);
System.out.println(Arrays.toString(numbers2)); // [6, 8, 10]
```

Берёт элементы с индекса `2` (включительно) до индекса `5` (**не включая**) — это уже знакомая логика, точно так же работают `substring()` и `Arrays.sort(arr, from, to)`.

**Главное отличие от `copyOf()`:** `copyOf()` всегда начинает копирование с **самого начала** массива (индекс 0). `copyOfRange()` позволяет вырезать кусок **из середины**, указывая откуда начать.

## 6. Глубина — что добавить сверх твоего конспекта

### А) Arrays.fill() — заполнить массив одним значением

```java
int[] arr = new int[5];
Arrays.fill(arr, 7);
System.out.println(Arrays.toString(arr)); // [7, 7, 7, 7, 7]
```

Полезно когда нужно создать массив с одинаковыми начальными значениями (например, доска для игры, заполненная нулями или специальным "пустым" значением).

Можно заполнить и **часть** массива, как с `sort()`:

```java
int[] arr = {1, 2, 3, 4, 5};
Arrays.fill(arr, 1, 4, 0); // заполнить индексы с 1 по 3 (4 не включая) нулями
System.out.println(Arrays.toString(arr)); // [1, 0, 0, 0, 5]
```

### Б) Arrays.binarySearch() — быстрый поиск элемента

```java
int[] arr = {1, 4, 5, 8, 9}; // массив ДОЛЖЕН быть отсортирован!
int index = Arrays.binarySearch(arr, 8);
System.out.println(index); // 3 — индекс числа 8
```

⚠️ **Критически важный момент:** этот метод работает **только** на **отсортированных** массивах. Если массив не отсортирован — результат будет непредсказуемым (метод может вернуть неправильный индекс или отрицательное число, даже если элемент реально есть в массиве):

```java
int[] arr = {9, 1, 5, 4, 8}; // НЕ отсортирован!
int index = Arrays.binarySearch(arr, 8);
System.out.println(index); // может быть НЕВЕРНЫЙ результат!
```

Если элемент **не найден** — метод возвращает отрицательное число (не `-1` как у `indexOf()` в строках, а более сложное значение, которое технически указывает куда элемент можно было бы вставить, но для базового использования просто проверяй `>= 0`):

```java
int[] arr = {1, 4, 5, 8, 9};
int index = Arrays.binarySearch(arr, 100);

if (index >= 0) {
    System.out.println("Найдено на индексе " + index);
} else {
    System.out.println("Элемент не найден");
}
```

### В) Зачем вообще нужен бинарный поиск, если есть обычный цикл

```java
// Обычный линейный поиск через цикл — проверяет ВСЕ элементы по очереди
int[] arr = {1, 4, 5, 8, 9};
int target = 8;
int foundIndex = -1;

for (int i = 0; i < arr.length; i++) {
    if (arr[i] == target) {
        foundIndex = i;
        break;
    }
}
```

Это работает всегда, но если массив **огромный** (миллионы элементов) — проверка каждого элемента по очереди медленная. `Arrays.binarySearch()` работает в разы быстрее на больших отсортированных массивах, потому что использует "умную" стратегию — делит массив пополам на каждом шаге, а не проверяет всё подряд. Это уже краешек темы алгоритмов которая будет в июле — но раз заговорили про методы массивов, важно понимать **зачем** существует этот конкретный метод, а не просто запомнить его синтаксис.

### Г) Arrays.asList() — превращение массива в список (забегая вперёд)

```java
import java.util.Arrays;
import java.util.List;

Integer[] arr = {1, 2, 3};
List<Integer> list = Arrays.asList(arr);
System.out.println(list); // [1, 2, 3]
```

Это уже немного предвосхищает будущую тему "коллекции" (`List`, `ArrayList`) — пока просто знай что такая возможность существует, для конвертации между обычным массивом и более гибкими структурами данных Java. Глубоко вникать сейчас не нужно.

## Итоговая таблица — все методы Arrays

|Метод|Что делает|Возвращает|
|---|---|---|
|`Arrays.toString(arr)`|Превращает массив в читаемую строку|`String`|
|`Arrays.sort(arr)`|Сортирует массив **на месте**|ничего (`void`)|
|`Arrays.sort(arr, from, to)`|Сортирует только часть массива|ничего (`void`)|
|`Arrays.equals(a, b)`|Сравнивает содержимое двух массивов|`boolean`|
|`Arrays.copyOf(arr, n)`|Копия первых `n` элементов (может дополнить нулями)|новый массив|
|`Arrays.copyOfRange(arr, from, to)`|Копия куска массива|новый массив|
|`Arrays.fill(arr, value)`|Заполняет весь массив одним значением|ничего (`void`)|
|`Arrays.binarySearch(arr, value)`|Быстрый поиск (только в отсортированном!)|индекс или отрицательное число|

---

## Главное что нужно запомнить из темы

1. `sort()`, `fill()` — **ничего не возвращают**, меняют массив "на месте"
2. `copyOf()`, `copyOfRange()` — **возвращают новый массив**, оригинал не трогают
3. Для сравнения массивов — всегда `Arrays.equals()`, никогда `.equals()` напрямую или `==`
4. `binarySearch()` работает **только** на отсортированных массивах
