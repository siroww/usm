## 1. Два способа обойти массив — сравнение

### Способ 1 — обычный for с индексом

```java
String[] numbers = {"one", "two", "three", "four", "five", "forty two"};

for (int i = 0; i < numbers.length; i++) {
    if (numbers[i].charAt(0) == 'f') {
        System.out.println(numbers[i]);
    }
}
```

Тут ты вручную управляешь счётчиком `i`, и через него обращаешься к элементу `numbers[i]`.

### Способ 2 — enhanced for (он же "for-each")

```java
String[] numbers = {"one", "two", "three", "four", "five", "forty two"};

for (String s : numbers) {
    if (s.charAt(0) == 'f') {
        System.out.println(s);
    }
}
```

**Результат у обоих способов одинаковый:**

```
four
five
forty two
```

## 2. Разбор синтаксиса enhanced for

```java
for (String s : numbers) {
```

Читается как: **"для каждого `s` в `numbers`"**.

- `String` — тип переменной `s`, должен **совпадать с типом элементов массива**
- `s` — имя переменной, которую ты сам придумываешь (можно назвать как угодно, не обязательно `s`)
- `:` — двоеточие, разделяет переменную и массив (твой конспект правильно это подметил — частая мелочь которую забывают)
- `numbers` — сам массив, по которому идёт обход

Java сама на каждой итерации берёт следующий элемент массива и кладёт его в переменную `s` — тебе не нужно думать про индексы вообще.

## 3. ⚠️ Главное отличие — работа со значением vs с копией

Это самый важный момент темы, и твой конспект очень правильно его выделил. Давай разберём **почему** так происходит, а не просто запомним факт.

```java
String[] numbers = {"one", "two", "three", "four", "five", "forty two"};

for (int i = 0; i < numbers.length; i++) {
    if (numbers[i].charAt(0) == 'f') {
        numbers[i] = "deleted"; // меняем элемент НАПРЯМУЮ через индекс
    }
}

System.out.println(numbers[3]); // deleted
```

В этом варианте `numbers[i] = "deleted"` — это **прямое обращение** к ячейке массива по адресу `i`. Ты буквально говоришь "положи новое значение вот в эту конкретную ячейку массива".

```java
String[] numbers1 = {"one", "two", "three", "four", "five", "forty two"};

for (String s : numbers1) {
    if (s.charAt(0) == 'f') {
        s = "deleted"; // меняем только ЛОКАЛЬНУЮ переменную s
    }
}

System.out.println(numbers1[3]); // four — ничего не изменилось!
```

А здесь `s = "deleted"` меняет **только саму переменную `s`** — это просто временная "коробка", в которую на каждой итерации копируется текущее значение элемента. Когда ты делаешь `s = "deleted"`, ты просто кладёшь новое значение в эту временную коробку, но **никак не трогаешь** оригинальный массив `numbers1`. После этой итерации `s` просто перезапишется следующим элементом массива, и временное значение "deleted" потеряется навсегда.

### Аналогия чтобы понять суть

Представь что массив — это полка с подписанными коробками. Обычный `for` с индексом даёт тебе **номер полки**, и ты можешь напрямую открыть нужную коробку и поменять что внутри. А `for-each` даёт тебе **копию содержимого** каждой коробки в руки, но ты не знаешь даже на какой она полке — поэтому как бы ты ни менял то, что у тебя в руках, оригинальная коробка на полке остаётся нетронутой.

## 4. Когда что использовать — практическое правило

|Хочу|Использовать|
|---|---|
|Просто прочитать/вывести/проверить элементы|`for-each` — код чище и короче|
|Изменить элементы массива|обычный `for` с индексом — обязательно|
|Нужен сам индекс для логики (например "элемент номер 3")|обычный `for` с индексом|
|Нужно сравнивать соседние элементы (`arr[i]` и `arr[i+1]`)|обычный `for` с индексом|
|Перебрать в обратном порядке|обычный `for` с индексом (`for-each` не умеет идти задом наперёд)|

## 5. Важный нюанс с примитивами vs объектами — то, чего нет в твоём конспекте

То, что показано в конспекте — это пример со `String`. Но похожая логика (хотя и по немного другой причине) работает и с примитивными типами вроде `int`:

```java
int[] nums = {1, 2, 3, 4, 5};

for (int n : nums) {
    n = n * 100; // меняем только локальную копию числа
}

System.out.println(Arrays.toString(nums)); // [1, 2, 3, 4, 5] — массив не изменился!
```

Здесь причина чуть проще для понимания, чем со строками: `int` — это **примитивный тип**, и когда `n` получает значение из массива, оно **копируется** в `n` буквально как число. Изменение `n` никак физически не связано с оригинальной ячейкой массива.

Со строками чуть сложнее концептуально (строки — это объекты, и там работает ещё и неизменяемость самих строк, о которой мы говорили в теме про методы String), но **итоговый эффект для тебя как программиста одинаковый**: в `for-each` ты никогда не можешь поменять исходный массив через переменную цикла, независимо от того, примитив там или объект.

## 6. Частая ошибка — попытка "удалить" элемент через for-each

Новички иногда пробуют так:

```java
String[] arr = {"a", "b", "c"};

for (String s : arr) {
    if (s.equals("b")) {
        s = null; // НЕ работает! Это не удаляет элемент из массива
    }
}
```

Это не сработает по той же причине — `s = null` меняет только временную переменную. К тому же у массивов **в принципе нет** операции "удалить элемент" — вспомни, размер массива фиксирован раз и навсегда. Если реально нужно "удалить" элемент — либо заменяешь его на специальное "пустое" значение через обычный `for` с индексом, либо (что чаще встретишь в будущем) переходишь на более гибкую структуру данных `ArrayList`, где удаление реально возможно — но это уже тема для другого дня.

## 7. Глубина — for-each на самом деле использует Iterator под капотом

Забегая немного вперёд: когда компилятор Java видит `for (String s : numbers)`, он **превращает** это в код, очень похожий на обычный `for` с индексом — это просто "синтаксический сахар" (удобная запись, которая на этапе компиляции разворачивается в более длинный код).

Для массивов это буквально превращается в:

```java
for (int i = 0; i < numbers.length; i++) {
    String s = numbers[i];
    // твой код
}
```

То есть **под капотом for-each — это тот же обычный for**, просто Java сама генерирует код с индексом за тебя, а тебе остаётся написать только суть. Это объясняет, кстати, и почему изменить массив через `s` не получается — ведь по сути `s` это просто обычная локальная переменная `String s = numbers[i]`, и это копия значения, как мы уже разобрали выше.

(Если работаешь не с массивом, а с другими структурами данных вроде `ArrayList`, под капотом там используется специальный объект `Iterator`, но для массивов всё именно так просто, как описано выше — пока не парься об этом, это будущая тема.)
