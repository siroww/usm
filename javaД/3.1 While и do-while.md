## 1. while — цикл с проверкой условия ДО выполнения

### Синтаксис

```java
while (условие) {
    // тело цикла
}
```

**Как это работает:** Java сначала проверяет условие. Если оно `true` — выполняет тело цикла, потом возвращается к проверке условия снова. И так до тех пор пока условие не станет `false`.

### Базовый пример

```java
int i = 1;

while (i <= 5) {
    System.out.println(i);
    i++;
}
```

**Результат:**

```
1
2
3
4
5
```

**Шаг за шагом что происходит:**

```
i = 1 → условие 1 <= 5 → true → печатаем 1 → i становится 2
i = 2 → условие 2 <= 5 → true → печатаем 2 → i становится 3
i = 3 → условие 3 <= 5 → true → печатаем 3 → i становится 4
i = 4 → условие 4 <= 5 → true → печатаем 4 → i становится 5
i = 5 → условие 5 <= 5 → true → печатаем 5 → i становится 6
i = 6 → условие 6 <= 5 → false → цикл останавливается
```

---

### ⚠️ Главная опасность — бесконечный цикл

Если забыть изменить переменную внутри цикла (например забыть `i++`) — условие никогда не станет `false`, и программа будет выполняться вечно, пока не зависнет или не вызовет ошибку памяти.

```java
int i = 1;

while (i <= 5) {
    System.out.println(i);
    // забыли i++ !
}
// БЕСКОНЕЧНЫЙ ЦИКЛ — будет печатать "1" вечно
```

**Золотое правило:** перед тем как написать `while`, сразу спрашивай себя — "что именно должно поменяться, чтобы условие стало `false`?" И сразу пиши это изменение внутри тела цикла, даже до того как напишешь остальную логику.

---

### Когда условие false с самого начала — цикл не выполнится вообще

```java
int i = 10;

while (i <= 5) {
    System.out.println(i); // этот код НЕ выполнится ни разу
}

System.out.println("После цикла");
```

**Результат:**

```
После цикла
```

Это важное отличие от `do-while`, смотри ниже.

## 2. do-while — цикл с проверкой условия ПОСЛЕ выполнения

### Синтаксис

```java
do {
    // тело цикла
} while (условие);
```

⚠️ Обрати внимание на точку с запятой `;` после `while(условие)` — это частая ошибка новичков, забывают её поставить.

**Как это работает:** Java **сначала выполняет тело цикла хотя бы один раз**, и только **потом** проверяет условие. Если условие `true` — повторяет, если `false` — останавливается.

### Базовый пример

```java
int i = 10;

do {
    System.out.println(i);
    i++;
} while (i <= 5);
```

**Результат:**

```
10
```

Видишь разницу? Хотя условие `i <= 5` с самого начала `false` (`10 <= 5` неверно) — тело цикла **всё равно выполнилось один раз**, потому что проверка происходит **после** выполнения, а не перед.

---

## 3. Главное отличие while vs do-while

|                                   | while                               | do-while                  |
| --------------------------------- | ----------------------------------- | ------------------------- |
| Когда проверяется условие         | **Перед** выполнением тела          | **После** выполнения тела |
| Минимальное количество выполнений | 0 раз (может не выполниться вообще) | **Минимум 1 раз**, всегда |

**Наглядное сравнение с одинаковым условием:**

```java
int x = 100;

// while — условие false с начала, цикл не выполнится ВООБЩЕ
while (x < 10) {
    System.out.println("while: " + x);
}

// do-while — выполнится ХОТЯ БЫ ОДИН РАЗ, даже если условие false
do {
    System.out.println("do-while: " + x);
} while (x < 10);
```

**Результат:**

```
do-while: 100
```

`while` ничего не вывел — условие сразу `false`. А `do-while` вывел один раз, потому что сначала выполняет, потом проверяет.

## 4. Когда использовать что — практический выбор

### Используй while, когда:

Не уверен, нужно ли выполнять тело цикла вообще, и это зависит от условия с самого начала.

```java
Scanner sc = new Scanner(System.in);
int number = sc.nextInt();

while (number != 0) {
    System.out.println("Введено: " + number);
    number = sc.nextInt();
}
System.out.println("Завершено (введён 0)");
```

### Используй do-while, когда:

Точно знаешь, что тело должно выполниться **хотя бы один раз**, независимо от условия. Классический пример — меню программы или запрос данных у пользователя, где сначала обязательно нужно показать что-то пользователю, а потом проверять, продолжать ли:

```java
Scanner sc = new Scanner(System.in);
int choice;

do {
    System.out.println("1 - Начать, 2 - Настройки, 0 - Выход");
    choice = sc.nextInt();
    System.out.println("Вы выбрали: " + choice);
} while (choice != 0);

System.out.println("Программа завершена");
```

Здесь меню **обязательно** должно показаться пользователю хотя бы раз, чтобы он мог сделать первый выбор — именно поэтому `do-while` подходит лучше чем `while`.

## 5. break и continue внутри циклов

### break — немедленно выйти из цикла

```java
int i = 1;

while (i <= 10) {
    if (i == 5) {
        break; // цикл останавливается прямо здесь
    }
    System.out.println(i);
    i++;
}
```

**Результат:**

```
1
2
3
4
```

Как только `i` стало равно `5` — сработал `break`, и цикл прервался полностью, даже не дойдя до `println(5)`.

---

### continue — пропустить текущую итерацию, перейти к следующей

```java
int i = 0;

while (i < 5) {
    i++;
    if (i == 3) {
        continue; // пропускаем печать именно для i == 3
    }
    System.out.println(i);
}
```

**Результат:**

```
1
2
4
5
```

Цифра `3` пропущена — когда выполнился `continue`, программа сразу прыгнула на проверку условия `i < 5`, не дойдя до `println()` в этой итерации.

⚠️ **Важная разница между break и continue:**

- `break` — **полностью** выходит из цикла, дальше код после цикла
- `continue` — **только** пропускает текущий проход, но цикл продолжается дальше

## 6. Глубина — на что обратить внимание

### А) Бесконечный цикл как осознанный приём

Иногда `while (true)` пишут специально, а выход делают через `break` внутри. Это используется когда условие выхода сложное и зависит от чего-то внутри тела цикла:

```java
Scanner sc = new Scanner(System.in);

while (true) {
    System.out.println("Введи число (0 для выхода): ");
    int num = sc.nextInt();
    
    if (num == 0) {
        break;
    }
    System.out.println("Квадрат числа: " + (num * num));
}
```

Это распространённый паттерн в реальном коде — не бойся `while (true)`, если есть `break` внутри, это нормально и осознанно, а не ошибка.

### Б) do-while используется реже чем while

На практике в реальных проектах `do-while` встречается заметно реже чем `while` или `for` — потому что ситуации "точно выполнить хотя бы раз" не так часто возникают. Не переживай если будешь реже его использовать — это нормально, просто держи в голове что он существует именно для этого специфического случая (меню, валидация ввода и подобное).
